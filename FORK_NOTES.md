# Lido Lend IRM Fork Notes

A fork of [Morpho Blue IRM](https://github.com/morpho-org/morpho-blue-irm) (Morpho Labs), extended for Lido Lend and imported as a subrepository into `lido-lend-markets`, the repository hosting the market and controller scaffolding around the `lido-lend` core. `AdaptiveCurveIrm` keeps the upstream curve math but swaps its hardcoded constants for per-market parameters (immutable `AdaptiveCurveConfig` contracts set by the `owner` or `manager`) and gains an optional `maxBorrowRate` cap. The upstream `FixedRateIrm` is removed and replaced by a fork-only `LinearKinkIrm` (an Aave/Compound-style kinked model). A fork-only proxied `IrmRouter` fronts both models — markets are created pointing at it and can be re-routed between them. `ExpLib`, `MathLib`, `UtilsLib` keep upstream behavior.

## Core changes

The curve formulas and the adaptation are **unchanged from upstream** — parameterized per market rather than modified. Differential fuzz tests assert exact equality against `test/CurveRefHelper.sol`, an independent reimplementation of the curve, adaptation, and cap, with configs fuzzed across the accepted space (the exactness policy in TEST_PLAN.md). The fork only changes where the parameters come from, who may set them, and adds an optional output cap.

- **Per-market config in its own immutable contract.** Upstream's six `ConstantsLib` curve constants (plus the new `maxBorrowRate`) become an `AdaptiveCurveParams` struct frozen into an `AdaptiveCurveConfig` contract, validated in its constructor. One `AdaptiveCurveConfig` holds one curve, and a market points at one.
- **Per-market config pointer + dedup cache on the IRM.** `AdaptiveCurveIrm` holds `mapping(Id => IAdaptiveCurveConfig) marketCurveConfig` and reads a market's parameters by an external static call to its `AdaptiveCurveConfig` (`getCurveParams()`) when computing the rate. A market with no config set reverts (`config not set`). It also holds `mapping(bytes32 => IAdaptiveCurveConfig) deployedCurveConfigs`, a cache keyed by `keccak256(abi.encode(params))` so identical parameters resolve to one shared, immutable config across markets. The only immutable is `ROUTER`.
- **Single privileged setter that deploys inline.** There is no separate factory. `setMarketCurveParams(marketParams, curveParams)` derives the market id, deploys `new AdaptiveCurveConfig(curveParams)` (which validates in its constructor) unless the dedup cache already holds one for those exact params, then points the market at the resolved config. It emits `ConfigDeployed` on a fresh deploy and `MarketCurveParamsSet` on every set. Callable by `owner` **or** `manager` only (`not authorized` otherwise). The IRM trusts the caller to choose well-formed params (no economic gate), matching Euler V2's core setter.
- **Owner and manager in storage.** `owner` rotates itself (`transferOwnership`) and the `manager` (`setManager`) — both owner-only, both rejecting the zero address — and may set market curves. `manager` is a scoped operational address that may only call `setMarketCurveParams`. Both initial roles are set by the constructor. See the router bullet below.
- **Reparametrization by re-pointing.** The owner or manager calls `setMarketCurveParams(marketParams, newParams)` again. The IRM resolves (deploys or reuses) the config, re-points the market, and clamps a non-zero stored `rateAtTarget` into the new band (a fresh market's 0 sentinel is left for the first-interaction seed). There is no in-place parameter setter (each `AdaptiveCurveConfig` is immutable). See the "Reparametrization" section of SPECIFICATION.md for the timing semantics.
- **Optional `maxBorrowRate` cap.** Hard ceiling on the charged rate (`0` disables it). It clamps the returned rate without touching the adapting `rateAtTarget`, so the state machine is unchanged.
- **Immutable IRMs behind a proxied router.** The IRMs are standalone, non-proxied contracts with the roles set at construction: `AdaptiveCurveIrm`'s constructor is `(router, owner, manager)` — `router` being the only address whose `borrowRate` calls are accepted — and `LinearKinkIrm`'s is `(owner, manager)`. There is no `initialize` and no impl-lock on them. IRM storage begins with the shared `OwnerManagerBase` fields — `owner` (slot 0) and `manager` (slot 1) — followed by each IRM's own appended fields: `rateAtTarget` (slot 2), `marketCurveConfig` (slot 3), and `deployedCurveConfigs` (slot 4) on the adaptive model, `marketKinkParams` (slot 2) on the kink model. (Inheriting the base moves `rateAtTarget` off upstream's slot 0 — harmless for a fresh, non-proxied deployment.) The proxied entity is the new `IrmRouter`: markets are created with the router as their `irm` — the one eternal address, since a market can never change its `irm` — and the router forwards `borrowRate` (Morpho-only, `not Morpho` otherwise) and `borrowRateView` (public) to `marketIrm[id]`, reverting `irm not set` when unrouted. `setMarketIrm(marketParams, irm)` is owner-or-manager gated, rejects the zero address (the mapping is never clearable), and requires `marketParams.irm` to be the router itself (`irm is not this router` otherwise — a mistyped `irm` field would derive a phantom id and leave the real market unrouted): for a live market it first calls `accrueInterest` (settling the elapsed period at the old model's rate), then probes the new impl with the exact `borrowRate` call Morpho will make — catching unpriceable markets and wrong-`ROUTER` impls, and seeding a fresh adaptive impl's `rateAtTarget` — then stores the pointer. A not-yet-created market is routed without touching the impl (nothing to accrue or brick, and a pre-creation probe would prematurely write a stateful model's state): `createMarket` performs the first ping itself and reverts, creating nothing, while the market is unrouted or its impl unconfigured. LidoLend has no separate `enableIrm` — the owner-gated `createMarket` enables the market's `irm` implicitly, so creating markets pointing at the router delegates the per-market impl choice to the router's `owner` (and the `manager` it appoints) forever. Router storage sits at an ERC-7201 namespaced base slot (`layout at`, namespace `lido.lend.storage.IrmRouter`): `owner` (base), `manager` packed with `isInitialized` (base + 1), `marketIrm` (base + 2), with the roles set once via `initialize(owner, manager)` behind the proxy (atomic with deployment, impl locked at construction). Upgrading the router logic is a proxy upgrade with `marketIrm` and both addresses persisting, and the router's proxy admin remains the ultimate authority (it can overwrite any slot via upgrade) until the proxy is ossified. The rate math itself is immutable — fixing an impl bug means deploying a new impl and migrating markets, not upgrading in place. The proxy lives in the product repo.

## Interfaces and libraries

- `IAdaptiveCurveTypes.sol` (new): the shared top-level `AdaptiveCurveParams` struct (the seven curve fields), decoupled from any contract.
- `IAdaptiveCurveConfig.sol` (new): the per-market config surface — `getCurveParams()` and the per-field getters (`CURVE_STEEPNESS()` … `MAX_BORROW_RATE()`). It inherits the `AdaptiveCurveParams` type from `IAdaptiveCurveTypes`.
- `IOwnerManager.sol` (new, `common/`): the two-role surface — `owner()`/`manager()`, `transferOwnership(address)`, `setManager(address)`, with `OwnershipTransferred`/`ManagerSet` events. There is no `initialize` here — a standalone contract sets the roles in its own constructor.
- `IIrmRouter.sol` (new, `irm-router/`): the router surface — `MORPHO()`, `marketIrm(Id)`, `setMarketIrm(MarketParams, IIrm)` (with the `MarketIrmSet` event), plus `isInitialized()` and the one-shot `initialize(owner, manager)`, inheriting `IIrm` and `IOwnerManager`.
- `IAdaptiveCurveIrm.sol`: renames `MORPHO()` to `ROUTER()` — the trusted caller is the router, not the core. Inherits the owner/manager surface from `IOwnerManager` (no `initialize` — the roles are constructor-set). Adds the `marketCurveConfig(Id)` and `deployedCurveConfigs(bytes32)` getters (return `IAdaptiveCurveConfig`), and `setMarketCurveParams(MarketParams, AdaptiveCurveParams)` (with `ConfigDeployed`/`MarketCurveParamsSet` events). `rateAtTarget(Id)` and the `IIrm` surface (`borrowRate`/`borrowRateView`) are unchanged.
- `ErrorsLib.sol`: renames `NOT_MORPHO` to `NOT_ROUTER` ("not router") to match the `ROUTER` gate, and adds `CONFIG_NOT_SET` plus the per-parameter validation errors thrown by `AdaptiveCurveConfig` (upstream had only `ZERO_ADDRESS` and `NOT_MORPHO`). `ZERO_ADDRESS` moves to the fork-new `common/OwnerManagerErrors.sol`, which also introduces `NOT_OWNER` and `NOT_AUTHORIZED`, shared by the IRMs and the router. The router adds its own `irm-router/libraries/ErrorsLib.sol` (`ALREADY_INITIALIZED`, `NOT_MORPHO`, `IRM_NOT_SET`, `NOT_ROUTER_MARKET`).
- `AdaptiveCurveIrmLib.sol` (periphery): resolves the market's config from the IRM (`marketCurveConfig(id)`) and reads it live (tracks the currently-registered config) instead of `ConstantsLib`, applying the same clamp, and reverts `config not set` when none is registered. Public surface unchanged, but behavior is now market-specific per the registered params — consumers that assumed the upstream constants must re-check.
- `ConstantsLib.sol`: moved from `src/` to `test/`, where it is the canonical default config the tests build on.

## Compatibility

- **Drop-in at the call site:** the `IIrm` surface keeps upstream signatures and semantics — Morpho and integrators are unaffected (a market must be routed at the router and have its params set before it is created).
- **Not drop-in at deployment:** the IRM constructors now take the roles — `AdaptiveCurveIrm(router, owner, manager)` with `router` the only address whose `borrowRate` calls are accepted, and `LinearKinkIrm(owner, manager)` — and markets are created with the proxied `IrmRouter` in front of the IRMs (`initialize(owner, manager)` atomic with proxy deployment) rather than with an IRM address directly. Curve params live in IRM-deployed `AdaptiveCurveConfig`s, and behavior is per-market.
- **Reparametrization is a re-pointing, not a setter:** the owner or manager sets new parameters via `setMarketCurveParams`, which can move the charged rate discontinuously on the next interaction (see the "Reparametrization" section in SPECIFICATION.md). Rotating `owner` or `manager` is a `transferOwnership` / `setManager` call.
- **Bumped:** `pragma 0.8.35` (was `0.8.19`), and core imports resolve to `lib/lido-lend`. **Unchanged:** MIT, `evm_version = "paris"`.

## Tests and verification

- Foundry: upstream tests are retained and adapted to the per-market-config model (the IRM is constructed with an owner and manager, and a default config from `test/ConstantsLib.sol` is set per market via `setMarketCurveParams`). `testConstants` is dropped (now covered by `AdaptiveCurveConfig` validation). Fork tests add config validation (`AdaptiveCurveConfigTest`), `setMarketCurveParams` deploy/dedup + authorization (`testSetConfigDeploysAndPrices`, `testSetConfigOnlyOwner`), ownership (`testTransferOwnership*`, `testDeployment`), the cap, config-space fuzzing, a config-parametrized curve oracle, curve edge cases, and reparametrization-by-re-pointing dynamics (`AdaptiveCurveIrmReparamTest`). `LinearKinkIrm` is covered by `test/LinearKinkIrmTest.sol`: rate shape at zero/kink/full utilization and per-leg linearity, statelessness (`borrowRate == borrowRateView`), fuzzed monotonicity and peak bound, over-utilization clamping, market independence, setter validation and authorization, and the shared `OwnerManagerBase` lifecycle (constructor-set roles, zero-address rejection, `transferOwnership`/`setManager`). The router is covered by `test/IrmRouterTest.sol` — forwarding and gates, the switch authorization (owner or manager), probe failures, accrue-before-switch, `createMarket` ordering, and a live-market migration scenario, against a mock of the core (a lightweight stand-in for `LidoLend.sol` that keeps the suite a unit test with direct market-state control) — and `test/IrmRouterProxyTest.sol` — `initialize` one-shot + impl lock, and upgrades preserving `marketIrm`, against a minimal test-only ERC-1967 proxy. See `TEST_PLAN.md` for the full mapping.
- Deep fuzz runs: the inherited `vm.assume`-heavy market filters are reworked into `bound`-based domain squeezing (`_boundMarket`), so the whole suite passes deep campaigns at Foundry's default rejection cap (verified at `FOUNDRY_FUZZ_RUNS=65536 FOUNDRY_INVARIANT_RUNS=4096`).
- Certora (`certora/{confs,specs}/`):
  - `BorrowRateView.conf` and `ExpectedMarketBalances.conf` prove the periphery equivalent to the contract (values and reverts).
  - `MaxBorrowRate.conf` proves the cap bounds both `borrowRate` and `borrowRateView` when enabled.
  - `RateAtTargetBand.conf` proves `borrowRate` keeps `rateAtTarget[id]` within `[minRateAtTarget, maxRateAtTarget]` and `setMarketCurveParams` clamps a non-zero stored rate into the new band at the swap.
  - `LinearKinkIrm.conf` (spec `certora/specs/LinearKinkIrm.spec`, the scene is the production contract alone, no harness) proves the fork-only kinked IRM never charges above the curve's peak (`baseRate + slope1 + slope2`) or `MAX_BORROW_RATE` — via the setter path, a `peakCapped` storage invariant, and a rate bound over any invariant-satisfying storage. It also proves the rate is monotone in utilization, `borrowRate == borrowRateView`, the `config not set` revert for an unconfigured market, and that the setter's parameters round-trip through the view (same-id agreement between `setMarketKinkParams` and `borrowRateView`, exact `baseRate`/peak read-back).
  - `IrmRouter.conf` (spec `certora/specs/IrmRouter.spec`) proves the router's forwarding equivalence (`borrowRateView` returns the routed implementation's value — the state-changing forward is summarized away by the probe model), its access control (`borrowRate` Morpho-only, the routing table moving only through authorized `setMarketIrm` calls and never back to zero, unrouted markets reverting on every pricing call), that `initialize` is one-shot, and the call-occurrence discipline of `setMarketIrm` — a not-yet-created market is routed without a single call into Morpho or the implementation (the pre-creation decay regression), while a live-market switch accrues and probes exactly once.
  - `MaxBorrowRate` and `RateAtTargetBand` read the curve params from a linked `AdaptiveCurveConfig`, while `BorrowRateView` and `ExpectedMarketBalances` summarize `getCurveParams()` with ghost-backed values so both sides of each equivalence see identical params. All confs pin `solc-0.8.35` — the LidoLend core compiles with the same solc as the IRM sources, so `ExpectedMarketBalances.conf` links `lib/lido-lend/src/LidoLend.sol` directly.
