# Lido Lend IRM Fork Notes

A fork of [Morpho Blue IRM](https://github.com/morpho-org/morpho-blue-irm) (Morpho Labs), extended for Lido lending and imported by the product repository as a subrepository. `AdaptiveCurveIrm` and its directly-coupled files change. The upstream `FixedRateIrm` is removed and replaced by a fork-only `LinearKinkIrm` (an Aave/Compound-style kinked model). A fork-only proxied `IrmRouter` fronts both models — markets are created pointing at it and can be re-routed between them. `ExpLib`, `MathLib`, `UtilsLib` keep upstream behavior.

## Fork point

- Upstream `morpho-org/morpho-blue-irm` @ `2bce6da3ebe910ceeec963781aa3f4b4322c296e` (PR #139, feat/balances-lib-2).
- Sources are vendored (this repo starts at its own `forge init`), so there is no shared git ancestor: the change record is this document plus the per-file diff against that commit. Inherited files are edited in place under their upstream names, and the untouched ones (`ExpLib`, `MathLib`, `UtilsLib`) are byte-identical to it.
- The Morpho core interfaces/libraries the IRM imports resolve to the `lib/morpho-blue` submodule — the public `morpho-org/morpho-blue`, the same core dependency upstream builds against.
- Upstream `AdaptiveCurveIrm` is the contract deployed [on Ethereum](https://etherscan.io/address/0x870aC11D48B15DB9a138Cf899d20F13F79Ba00BC) — this fork's bytecode no longer matches it.

Reproduce the diff:

```sh
git clone https://github.com/morpho-org/morpho-blue-irm /tmp/mbi
git -C /tmp/mbi checkout 2bce6da3ebe910ceeec963781aa3f4b4322c296e
diff -rq src /tmp/mbi/src
```

One instance serves many markets keyed by `Id` (like AdaptiveCurveIrm): each market's params (`baseRate`, `slope1`, `slope2`, `optimalUtilization`) live packed in a single slot (4×`uint64`, per-second WAD) in a `mapping(Id => LinearKinkParams)`, set and reparametrized in place by `owner`/`manager` via `setMarketKinkParams(marketParams, params)`. A market with no params set reverts `config not set`. Owner/manager set at construction, immutable behind the router, as in AdaptiveCurveIrm. Specified in the "LinearKinkIrm" part of SPECIFICATION.md.

It forwards `borrowRate`/`borrowRateView` to the per-market implementation in `mapping(Id => IIrm) marketIrm`, switchable by the router `owner` or `manager` via `setMarketIrm`, so a live market can migrate between rate models. Specified in the "IrmRouter" part of SPECIFICATION.md.
- **Added** (fork-only): the shared `common/` module — `OwnerManagerBase.sol` (abstract), `IOwnerManager.sol`, `OwnerManagerErrors.sol` — the two-role (owner/manager) authorization logic: the roles, their setters, and the `_checkOwner`/`_checkAuthorized` gates. A standalone contract (both IRMs) sets the initial roles in its own constructor. The proxied router declares its own one-shot `initialize(owner, manager)` and impl-lock on top of the same base. Base storage (`owner`, then `manager`) opens each inheriting contract's layout.
- **Relocated**: `libraries/ConstantsLib.sol` moved to `test/` (the canonical default config the tests build on, upstream-only here).
- Everything else is identical.

## Core changes

The curve math and its adaptation are **byte-identical to upstream**. The fork only changes where the curve parameters come from, who may set them, and adds an optional output cap.

- **Per-market config in its own immutable contract.** Upstream's six `ConstantsLib` curve constants (plus the new `maxBorrowRate`) become an `AdaptiveCurveParams` struct frozen into an `AdaptiveCurveConfig` contract, validated in its constructor. One `AdaptiveCurveConfig` holds one curve, and a market points at one.
- **Per-market config pointer + dedup cache on the IRM.** `AdaptiveCurveIrm` holds `mapping(Id => IAdaptiveCurveConfig) marketCurveConfig` and reads a market's parameters by an external static call to its `AdaptiveCurveConfig` (`getCurveParams()`) when computing the rate. A market with no config set reverts (`config not set`). It also holds `mapping(bytes32 => IAdaptiveCurveConfig) deployedCurveConfigs`, a cache keyed by `keccak256(abi.encode(params))` so identical parameters resolve to one shared, immutable config across markets. The only immutable is `ROUTER`.
- **Single privileged setter that deploys inline.** There is no separate factory. `setMarketCurveParams(marketParams, curveParams)` derives the market id, deploys `new AdaptiveCurveConfig(curveParams)` (which validates in its constructor) unless the dedup cache already holds one for those exact params, then points the market at the resolved config. It emits `ConfigDeployed` on a fresh deploy and `MarketCurveParamsSet` on every set. Callable by `owner` **or** `manager` only (`not authorized` otherwise). The IRM trusts the caller to choose well-formed params (no economic gate), matching Euler V2's core setter.
- **Owner and manager in storage.** `owner` rotates itself (`transferOwnership`) and the `manager` (`setManager`) — both owner-only, both rejecting the zero address — and may set market curves. `manager` is a scoped operational address that may only call `setMarketCurveParams`. Both initial roles are set by the constructor. See the router bullet below.
- **Reparametrization by re-pointing.** The owner or manager calls `setMarketCurveParams(marketParams, newParams)` again. The IRM resolves (deploys or reuses) the config and re-points the market while `rateAtTarget` persists. There is no in-place parameter setter (each `AdaptiveCurveConfig` is immutable). See the "Reparametrization" section of SPECIFICATION.md for the timing/snap semantics.
- **Optional `maxBorrowRate` cap.** Hard ceiling on the charged rate (`0` disables it). It clamps the returned rate without touching the adapting `rateAtTarget`, so the state machine is unchanged.
- **Immutable IRMs behind a proxied router.** The IRMs are standalone, non-proxied contracts with the roles set at construction: `AdaptiveCurveIrm`'s constructor is `(router, owner, manager)` — `router` being the only address whose `borrowRate` calls are accepted — and `LinearKinkIrm`'s is `(owner, manager)`. There is no `initialize` and no impl-lock on them. IRM storage begins with the shared `OwnerManagerBase` fields — `owner` (slot 0) and `manager` (slot 1) — followed by each IRM's own appended fields: `rateAtTarget` (slot 2), `marketCurveConfig` (slot 3), and `deployedCurveConfigs` (slot 4) on the adaptive model, `marketKinkParams` (slot 2) on the kink model. (Inheriting the base moves `rateAtTarget` off upstream's slot 0 — harmless for a fresh, non-proxied deployment.) The proxied entity is the new `IrmRouter`: markets are created with the router as their `irm` — the one eternal address, since a market can never change its `irm` — and the router forwards `borrowRate` (Morpho-only, `not Morpho` otherwise) and `borrowRateView` (public) to `marketIrm[id]`, reverting `irm not set` when unrouted. `setMarketIrm(marketParams, irm)` is owner-or-manager gated, rejects the zero address (the mapping is never clearable), and requires `marketParams.irm` to be the router itself (`irm is not this router` otherwise — a mistyped `irm` field would derive a phantom id and leave the real market unrouted): for a live market it first calls `accrueInterest` (settling the elapsed period at the old model's rate), then probes the new impl with the exact `borrowRate` call Morpho will make — catching unpriceable markets and wrong-`ROUTER` impls, and pre-seeding an adaptive impl's `rateAtTarget` — then stores the pointer. Ordering for a new market: impl config → `setMarketIrm` → `createMarket` (creation pings `borrowRate`). Morpho's `enableIrm` whitelists only the router, delegating the per-market impl choice to the router `owner` (and the `manager` it appoints) forever. Router storage sits at an ERC-7201 namespaced base slot (`layout at`, namespace `lido.lend.storage.IrmRouter`): `owner` (base), `manager` packed with `isInitialized` (base + 1), `marketIrm` (base + 2), with the roles set once via `initialize(owner, manager)` behind the proxy (atomic with deployment, impl locked at construction). Upgrading the router logic is a proxy upgrade with `marketIrm` and both addresses persisting, and the router's proxy admin remains the ultimate authority (it can overwrite any slot via upgrade) until the proxy is ossified. The rate math itself is immutable — fixing an impl bug means deploying a new impl and migrating markets, not upgrading in place. The proxy lives in the product repo.

## Interfaces and libraries

- `IAdaptiveCurveTypes.sol` (new): the shared top-level `AdaptiveCurveParams` struct (the seven curve fields), decoupled from any contract.
- `IAdaptiveCurveConfig.sol` (new): the per-market config surface — `getCurveParams()` and the per-field getters (`CURVE_STEEPNESS()` … `MAX_BORROW_RATE()`). It inherits the `AdaptiveCurveParams` type from `IAdaptiveCurveTypes`.
- `IOwnerManager.sol` (new, `common/`): the two-role surface — `owner()`/`manager()`, `transferOwnership(address)`, `setManager(address)`, with `OwnershipTransferred`/`ManagerSet` events. There is no `initialize` here — a standalone contract sets the roles in its own constructor.
- `IIrmRouter.sol` (new, `irm-router/`): the router surface — `MORPHO()`, `marketIrm(Id)`, `setMarketIrm(MarketParams, IIrm)` (with the `MarketIrmSet` event), plus `isInitialized()` and the one-shot `initialize(owner, manager)`, inheriting `IIrm` and `IOwnerManager`.
- `IAdaptiveCurveIrm.sol`: drops the per-deployment curve getters and `getCurveParams()`. Inherits the owner/manager surface from `IOwnerManager` (no `initialize` — the roles are constructor-set). Adds the `marketCurveConfig(Id)` and `deployedCurveConfigs(bytes32)` getters (return `IAdaptiveCurveConfig`), and `setMarketCurveParams(MarketParams, AdaptiveCurveParams)` (with `ConfigDeployed`/`MarketCurveParamsSet` events). Renames `MORPHO()` to `ROUTER()` — the trusted caller is the router, not Morpho. `rateAtTarget(Id)` and the `IIrm` surface (`borrowRate`/`borrowRateView`) are unchanged.
- `ErrorsLib.sol`: renames `NOT_MORPHO` to `NOT_ROUTER` ("not router") to match the `ROUTER` gate, keeps the per-parameter validation errors (now thrown by `AdaptiveCurveConfig`), and adds `CONFIG_NOT_SET`. The owner/manager errors (`ZERO_ADDRESS`, `NOT_OWNER`, `NOT_AUTHORIZED`, `ALREADY_INITIALIZED`) moved to `common/OwnerManagerErrors.sol` shared by the IRMs and the router. The router adds its own `irm-router/libraries/ErrorsLib.sol` (`NOT_MORPHO`, `IRM_NOT_SET`, `NOT_ROUTER_MARKET`).
- `AdaptiveCurveIrmLib.sol` (periphery): resolves the market's config from the IRM (`marketCurveConfig(id)`) and reads it live (tracks the currently-registered config) instead of `ConstantsLib`, applying the same clamp, and reverts `config not set` when none is registered. Public surface unchanged, but behavior is now market-specific per the registered params — consumers that assumed the upstream constants must re-check.
- `ConstantsLib.sol`: moved from `src/` to `test/`, where it is the canonical default config the tests build on.

## Compatibility

- **Drop-in at the call site:** the `IIrm` surface keeps upstream signatures and semantics — Morpho and integrators are unaffected (a market must be routed at the router and have its params set before it is created).
- **Not drop-in at deployment:** the IRM constructors now take the roles — `AdaptiveCurveIrm(morpho, owner, manager)` with `morpho` the address whose calls `borrowRate` accepts (the router in production), and `LinearKinkIrm(owner, manager)` — and markets are created with the proxied `IrmRouter` in front of the IRMs (`initialize(owner, manager)` atomic with proxy deployment) rather than with an IRM address directly. Curve params live in IRM-deployed `AdaptiveCurveConfig`s, and behavior is per-market.
- **Reparametrization is a re-pointing, not a setter:** the owner or manager sets new parameters via `setMarketCurveParams`, which can move the charged rate discontinuously on the next interaction (see the "Reparametrization" section in SPECIFICATION.md). Rotating `owner` or `manager` is a `transferOwnership` / `setManager` call.
- **Bumped:** `pragma 0.8.35` (was `0.8.19`), and Morpho core imports resolve to `lib/morpho-blue`. **Unchanged:** MIT, `evm_version = "paris"`.

## Tests and verification

- Foundry: upstream tests are retained and adapted to the per-market-config model (the IRM is constructed with an owner and manager, and a default config from `test/ConstantsLib.sol` is set per market via `setMarketCurveParams`). `testConstants` is dropped (now covered by `AdaptiveCurveConfig` validation). Fork tests add config validation (`AdaptiveCurveConfigTest`), `setMarketCurveParams` deploy/dedup + authorization (`testSetConfigDeploysAndPrices`, `testSetConfigOnlyOwner`), ownership (`testTransferOwnership*`, `testDeployment`), the cap, config-space fuzzing, a config-parametrized curve oracle, curve edge cases, and reparametrization-by-re-pointing dynamics (`AdaptiveCurveIrmReparamTest`). `LinearKinkIrm` is covered by `test/LinearKinkIrmTest.sol`: rate shape at zero/kink/full utilization and per-leg linearity, statelessness (`borrowRate == borrowRateView`), fuzzed monotonicity and peak bound, over-utilization clamping, market independence, setter validation and authorization, and the shared `OwnerManagerBase` lifecycle (constructor-set roles, zero-address rejection, `transferOwnership`/`setManager`). The router is covered by `test/IrmRouterTest.sol` — forwarding and gates, the switch authorization (owner or manager), probe failures, accrue-before-switch, `createMarket` ordering, and a live-market migration scenario, against a mock Morpho (the real `Morpho.sol` pins `pragma 0.8.19` exactly and cannot compile with the `0.8.35` sources) — and `test/IrmRouterProxyTest.sol` — `initialize` one-shot + impl lock, and upgrades preserving `marketIrm`, against a minimal test-only ERC-1967 proxy. See `TEST_PLAN.md` for the full mapping.
- Deep fuzz runs: the inherited `vm.assume`-heavy market filters are reworked into `bound`-based domain squeezing (`_boundMarket`), so the whole suite passes deep campaigns at Foundry's default rejection cap (verified at `FOUNDRY_FUZZ_RUNS=65536 FOUNDRY_INVARIANT_RUNS=4096`).
- Certora (`certora/{confs,specs}/`):
  - `BorrowRateView.conf` and `ExpectedMarketBalances.conf` prove the periphery equivalent to the contract (values and reverts).
  - `MaxBorrowRate.conf` proves the cap bounds both `borrowRate` and `borrowRateView` when enabled.
  - `RateAtTargetBand.conf` proves `borrowRate` keeps `rateAtTarget[id]` within `[minRateAtTarget, maxRateAtTarget]`.
  - `LinearKinkIrm.conf` (spec `certora/specs/LinearKinkIrm.spec`, the scene is the production contract alone, no harness) proves the fork-only kinked IRM never charges above the curve's peak (`baseRate + slope1 + slope2`) or `MAX_BORROW_RATE` — via the setter path, a `peakCapped` storage invariant, and a rate bound over any invariant-satisfying storage. It also proves the rate is monotone in utilization, `borrowRate == borrowRateView`, the `config not set` revert for an unconfigured market, and that the setter's parameters round-trip through the view (same-id agreement between `setMarketKinkParams` and `borrowRateView`, exact `baseRate`/peak read-back).
  - `IrmRouter.conf` (spec `certora/specs/IrmRouter.spec`) proves the router's forwarding equivalence (`borrowRateView` returns the routed implementation's value — the state-changing forward is summarized away by the probe model), its access control (`borrowRate` Morpho-only, the routing table moving only through owner-called `setMarketIrm` and never back to zero, unrouted markets reverting on every pricing call), and that `initialize` is one-shot.
  - The adaptive specs/harness read the curve params from a linked `AdaptiveCurveConfig`. Confs pin `solc-0.8.35`, except `ExpectedMarketBalances.conf`, which compiles `lib/morpho-blue/src/Morpho.sol` with `solc-0.8.19` via a per-file `solc_map` (Morpho core pins `pragma solidity 0.8.19` exactly, so a single solc cannot compile it together with the `0.8.35` sources).
